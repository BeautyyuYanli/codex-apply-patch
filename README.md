# codex-apply-patch

A standalone, automatically updated mirror of
[`codex-rs/apply-patch`](https://github.com/openai/codex/tree/main/codex-rs/apply-patch).
This repository is itself the `apply-patch` crate: the synchronized `src`,
`tests`, and `BUILD.bazel` live at the top level and remain unmodified.
`sync/sync.py` expands the upstream workspace metadata into a standalone
`Cargo.toml` and pins Codex's internal crates to the exact same upstream commit.

## Build

```sh
cargo build --locked --release --bin apply_patch
```

The binary is written to `target/release/apply_patch`.

## Synchronization

Run the source generator manually with:

```sh
uv run --script sync/sync.py --ref main
```

The generator:

- fetches the requested OpenAI Codex branch, tag, or commit;
- replaces the root `src`, `tests`, and `BUILD.bazel` with the upstream files;
- resolves inherited package and dependency metadata into a standalone
  `Cargo.toml`;
- pins internal Codex crates to the synchronized commit;
- copies the upstream Apache-2.0 `LICENSE` and `NOTICE`;
- records the upstream ref, commit, and tree hash; and
- regenerates `Cargo.lock`.

`Cargo.toml`, `Cargo.lock`, `LICENSE`, `NOTICE`, `src`, `tests`, `BUILD.bazel`,
and the commit/ref/tree files under `sync/state` are generated and should
not be edited manually.

## Automation and releases

The daily workflow gives upstream releases priority:

1. If OpenAI Codex has published one or more releases since the recorded
   release ID, each release tag is synchronized and built in chronological
   order. The mirror creates the same tag, title, body, and prerelease status,
   with an `apply-patch` Linux x86-64 binary bundle attached. The main branch
   ends on the newest release snapshot for that day.
2. If there is no new release, the workflow synchronizes `main`. A binary
   artifact is built only when the upstream commit hash changed.

Release bundles include the binary, upstream `LICENSE` and `NOTICE`, source
provenance, SHA-256 checksum, and third-party license texts generated by
[`cargo-about`](https://github.com/EmbarkStudios/cargo-about).

The initial `sync/state/release-id` is intentionally seeded to the newest
release that existed when this repository was created, so automation mirrors
new releases rather than backfilling the entire Codex release history.
